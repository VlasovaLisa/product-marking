# 04. Веб-приложение (Flask)

> **Статус 2026-11-15:** реализовано и проверено: `src/app.py`, `src/templates/index.html`, `tests/test_app.py` (12 тестов). Реальный прогон: кадр ММК через `python -m src.app` (порт 8000) распознан за 12–14 с, ошибки для `.gif` и битого `.jpg` — HTTP 400 с сообщением; проверка в Google Chrome: загрузка, превью, распознавание, редактирование. **Не проверено:** Firefox (НФТ 5), сообщение «Маркировка не распознана» в браузере (покрыто тестом сервера), файл больше 10 МБ в браузере.

## Цель

Минимальный веб-интерфейс, через который пользователь загружает фото, запускает распознавание, видит исходное изображение и результат и может вручную исправить текст.

- Интерфейс `recognize(image) -> RecognitionResult` из этапа 3. До его готовности используется стаб с той же сигнатурой.

## Задачи

### Сервер
- [ ] `src/app.py`: фабрика `create_app(recognizer)`. Распознаватель передаётся снаружи: в тестах — стаб, в продакшене — настоящий конвейер.
- [ ] OCR-модель загружается один раз при старте сервера, а не на каждый запрос (НФТ 2).
- [ ] `GET /` — страница интерфейса.
- [ ] `POST /recognize` — принимает файл, возвращает JSON: `text`, `angle`, `elapsed_seconds`, `status` ∈ {`ok`, `partial`, `not_recognized`}, либо ошибку.
- [ ] Ограничение размера загрузки (`MAX_CONTENT_LENGTH`, *решение исполнителя*, например 10 МБ).

### Валидация файла (ФТ 1, 7)
- [ ] Допустимые расширения: `.jpg`, `.jpeg`, `.png` (без учёта регистра).
- [ ] Проверка содержимого: файл декодируется `cv2.imdecode`; если нет — «файл повреждён». Проверка только расширения недостаточна.
- [ ] Понятные сообщения об ошибке на русском для неподдерживаемого формата, повреждённого файла и пустого запроса. HTTP 400.

### Интерфейс (п. 6, ФТ 5, 6, 8, 9)
- [ ] Одна страница: кнопка загрузки изображения, область предварительного просмотра (показывается сразу после выбора файла), кнопка «Распознать», редактируемое текстовое поле (`<textarea>`) с результатом.
- [ ] Индикатор обработки, пока идёт распознавание (оно может занимать десятки секунд); кнопка блокируется на время запроса.
- [ ] Частичный результат показывается в поле как есть и доступен для правки (ФТ 8).
- [ ] Пустой результат → сообщение «Маркировка не распознана» (дословно по ТЗ), поле остаётся пустым и доступным для ручного ввода (ФТ 9, критерий 10).
- [ ] Отредактированный текст никуда не сохраняется: истории и БД в MVP нет (п. 8). Допустима кнопка «Скопировать» (*решение исполнителя*).
- [ ] Vanilla HTML/CSS/JS без сборщиков, чтобы не усложнять установку (НФТ 6).

### Проверка
- [ ] Smoke-тесты через Flask test client со стабом распознавателя: успешный ответ, частичный, пустой → `not_recognized`, неверное расширение, повреждённый файл, отсутствие файла.
- [ ] Ручная проверка в актуальных Google Chrome и Firefox: загрузка JPG и PNG, превью, распознавание, правка текста, сообщения об ошибках (НФТ 5).
- [ ] Проверка, что после запуска сервера всё делается в браузере, без командной строки (НФТ 7).
- [ ] Замер полного времени запроса на реальном конвейере (≤ 60 с, НФТ 2).

## Критерии готовности

- Пользователь открывает приложение в браузере, загружает изображение и запускает распознавание (критерий 2).
- Распознанный текст показывается и редактируется (критерии 3, 7).
- «Маркировка не распознана» выводится при пустом результате, ручной ввод доступен (критерий 10).
- Неподдерживаемые и повреждённые файлы дают понятную ошибку (ФТ 7).
- Работает в Chrome и Firefox. Smoke-тесты проходят.

## Риски этапа

- Долгий запрос обрывается по таймауту браузера или dev-сервера → индикатор прогресса, проверка таймаутов; при необходимости уменьшение времени конвейера на этапе 3.
- Повторная загрузка модели на каждый запрос → модель создаётся один раз в `create_app`.
- EXIF-ориентация JPG у фото с телефона → учесть при декодировании (у кадров с камеры конвейера EXIF нет, но пользователь может загрузить и другое фото).
