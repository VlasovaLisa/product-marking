# 03. OCR-конвейер и оценка качества

## Цель

Собрать и настроить на выборке для настройки конвейер «предобработка → ориентация → OCR → постобработка» с CER ≤ 30% и временем ≤ 60 с на изображение на CPU. Зафиксировать его как единый интерфейс для веб-приложения и итоговой оценки.

## Пункты ТЗ

- п. 3.2 — CER ≤ 30%, ≤ 60 с на изображение.
- п. 4.3 «Автоматическая обработка», шаги 2–4.
- п. 4.4 — оценка по всей выборке и по каждому производителю, пороги по производителям не обязательны.
- п. 5 — EasyOCR как основной вариант, PaddleOCR при недостаточном качестве, выбор ориентации сравнением повёрнутых версий, простая постобработка.
- ФТ 2, 3, 4, 10. НФТ 1, 2, 4.
- Риски 1, 2, 3, 5, 6.

## Входы и зависимости

- `data/split.csv`, `data/labels.csv`, `normalize()` из этапа 2.
- Повёрнутые копии выборки настройки из этапа 2.
- **Используется только `split == tune`.** Тест на этом этапе не открывается (п. 4.2).

> **Изменение эталона (решение 2026-11-14, требует согласования с заказчиком).** Эталон — не полный текст маркировки, а поля из имени файла: плавка и лист (`data/references.csv`). CER поля = расстояние Левенштейна от эталона до *наилучшего совпадающего фрагмента* текста OCR (посторонний текст не штрафуется) / длина эталона. Нормализация для сравнения: `normalize_field` (верхний регистр, только буквы и цифры).
>
> Решения, принятые по данным (подробности в [../experiments.md](../experiments.md)):
> - **Год в эталоне.** У ММК на листе напечатано `2023-В105741`, у `V`/`Z` — только код плавки (`V30336`), без года. Поэтому `ref_heat` для `V`/`Z` без года (`src/references.py`). Это проверено по выходу OCR на выборке настройки (доля найденных плавок у `V`/`Z` выросла с 0–2,5% до 32,5%).
> - **Короткий лист.** У `V`/`Z` лист — 1–2 цифры, такой фрагмент найдётся в любом тексте. Поле исключено из CER (`is_measurable` в `src/metrics.py`), основной показатель для них — плавка.
> - **Тест** по-прежнему не открывается до этапа 5.

## Задачи

### Метрика и оценка
- [ ] `src/metrics.py`: `cer(reference, hypothesis)` = (замены + удаления + вставки) / длина эталона, по расстоянию Левенштейна на нормализованном тексте. Юнит-тесты на краевые случаи: пустая гипотеза, пустой эталон, идентичные строки.
- [ ] Агрегирование: суммарные правки / суммарная длина эталонов (micro-CER) — основная цифра; средний CER по изображениям — справочно (*решение исполнителя*, записать в отчёт).
- [ ] `scripts/evaluate.py --split tune|test --config <конфиг>`: прогоняет конвейер, считает CER общий и по производителям, время на изображение (среднее, медиана, максимум), исключает `unreadable`, сохраняет CSV с построчными результатами для анализа ошибок.
- [ ] Флаг `--split test` блокируется до этапа 5 (явное подтверждение), чтобы тест не использовался случайно.

### Базовый замер
- [ ] EasyOCR `Reader(['ru', 'en'], gpu=False)` без предобработки и поворотов на размеченном поднаборе настройки. Записать CER и время — это точка отсчёта.

### Предобработка OpenCV (ФТ 2, риск 1, 5)
Каждый шаг включается в итоговый конвейер, только если улучшает CER на выборке настройки. Результаты сравнения записываются.
- [ ] Маска оверлея камеры (дата/время в левом верхнем углу).
- [ ] Перевод в оттенки серого.
- [ ] Выравнивание контраста (CLAHE) против бликов и неравномерного освещения.
- [ ] Шумоподавление / морфология (особенно для точечной маркировки «Уральской Стали»: замыкание точек в штрихи).
- [ ] Масштабирование: изображения 1280×720, поэтому уменьшение, скорее всего, не нужно. Проверить и увеличение мелкого текста, и уменьшение ради скорости (риск 5).

### Ориентация (ФТ 3, риск 2)
- [ ] Прогон OCR на 0°, 90°, 180°, 270°, выбор варианта по средней уверенности OCR, взвешенной на длину распознанного текста (*решение исполнителя*, альтернативы сравниваются: доля символов из алфавита маркировки, совпадение с шаблонами плавки).
- [ ] Учесть, что маркировка на кадрах часто наклонена под произвольным углом (не кратным 90°). Проверить, справляется ли детектор EasyOCR с наклоном сам (`rotation_info`) или нужен дополнительный выравнивающий поворот.
- [ ] Проверка на повёрнутых копиях выборки настройки: доля правильно выбранных ориентаций и CER на каждом угле.
- [ ] Контроль времени: 4 прогона OCR должны укладываться в 60 с на CPU. Если нет — ранний выход при высокой уверенности или выбор ориентации по более дешёвому признаку.

### Постобработка (п. 5)
- [ ] Удаление символов вне алфавита маркировки (цифры, кириллица/латиница из реальных маркировок, `-`, `,`, `х`, `.`).
- [ ] Контекстная замена похожих символов (`О`↔`0`, `В`↔`8`, п. 4.1): например, внутри числовых последовательностей → цифры. Правила не должны зависеть от знания производителя (ФТ 10).
- [ ] Фильтрация мусорных детекций по уверенности и размеру бокса.
- [ ] Упорядочивание строк сверху вниз — согласовано с правилами разметки этапа 2.

### Сравнение с PaddleOCR (риски 3, 6)
- [ ] Тот же поднабор настройки, та же предобработка и нормализация: CER общий и по производителям, время на CPU, сложность установки.
- [ ] Решение (EasyOCR / PaddleOCR) и обоснование записываются в `docs/ocr-model-choice.md`. По ТЗ EasyOCR основной; PaddleOCR берём, только если он заметно лучше по CER и укладывается в НФТ 2, 4, 6. Отступление от НФТ 3 явно отмечается.

### Единый интерфейс
- [ ] `src/pipeline.py`: `recognize(image: np.ndarray) -> RecognitionResult` с полями `text`, `lines`, `confidence`, `angle`, `elapsed_seconds`. Пустой `text` означает «текст не обнаружен».
- [ ] OCR-модель создаётся один раз и передаётся в конвейер через конструктор или аргумент (удобно для тестов и веба).
- [ ] Параметры конвейера — в одном конфиге (`config.yaml` или dataclass), который используют и `evaluate.py`, и веб.
- [ ] Сигнатура фиксируется рано, чтобы этап 4 мог стартовать параллельно.

## Артефакты

- `scripts/evaluate.py`.
- Журнал экспериментов (`docs/experiments.md`): конфигурация → CER общий и по производителям → время.
- `docs/ocr-model-choice.md`.
- Зафиксированный конфиг конвейера.

## Критерии готовности

- На размеченном поднаборе настройки CER ≤ 30% с запасом (ориентир — заметно ниже порога, потому что на тесте результат может быть хуже).
- Ориентация правильно определяется на повёрнутых копиях выборки настройки.
- Время на изображение ≤ 60 с на CPU с учётом перебора поворотов.
- Конфиг конвейера зафиксирован, тест ни разу не запускался.

## Риски этапа

- Точечная маркировка распознаётся плохо → морфология на предобработке, сравнение с PaddleOCR, анализ ошибок по производителю.
- Перебор 4 поворотов слишком медленный → ранний выход, уменьшение разрешения, предварительный выбор ориентации по детекции.
- Переобучение настроек на маленьком размеченном поднаборе → контроль на частичном эталоне (плавка + лист из имени) по всей выборке настройки.
