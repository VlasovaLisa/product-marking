# 01. Каркас проекта и аудит данных

## Цель

Подготовить репозиторий и окружение, проверить целостность изображений и собрать единую таблицу метаданных с производителем и ключом группировки для каждого фото.

## Пункты ТЗ

- п. 4.1 — особенности исходных данных, производители.
- п. 4.3 «Разовая подготовка», шаги 1–2: удаление повреждённых файлов, определение производителя.
- НФТ 3 — Python 3.10+, EasyOCR, OpenCV, Flask.

## Входы и зависимости

- `images/` — 2906 JPG.
- Зависимостей от других этапов нет.

## Задачи

### Каркас
- [x] `git init`, `.gitignore`: `images/`, `data/rotated/`, `.venv/`, `__pycache__/`, кэш моделей, отчёты прогонов.
- [x] Структура: `src/` (код конвейера и приложения), `scripts/` (разовые скрипты подготовки и оценки), `data/` (CSV-метаданные, разметка, разбиение), `tests/`.
- [x] `requirements.txt` (черновик): `easyocr`, `opencv-python-headless`, `flask`, `numpy`, `pandas`, `pytest`. Версии фиксируются на этапе 5.
- [x] Проверка, что окружение ставится на Python 3.10+ и EasyOCR запускается на CPU (`gpu=False`).
- [x] Путь к папке с изображениями задаётся конфигом или переменной окружения, без хардкода абсолютных путей.

### Аудит изображений (п. 4.3.1)
- [x] `scripts/audit_images.py`: для каждого файла `cv2.imread`, проверка на `None`, нулевой размер, неожиданное разрешение.
- [x] Битые файлы не удаляются из `images/`: они помечаются в метаданных (`is_corrupted`) и исключаются из дальнейшей работы. Их количество фиксируется.

### Метаданные
- [x] `scripts/build_metadata.py` → `data/metadata.csv` с колонками: `image_id` (номер трубы), `filename`, `heat` (плавка, например `2023-В303529`), `sheet` (номер листа), `heat_prefix` (`В`/`V`/`Z`), `manufacturer`, `marking_format`, `group_key` (= `heat` + `sheet`), `is_corrupted`.
- [x] Учесть, что `В` в префиксе — кириллица, а `V`/`Z` — латиница. Нормализацию символов не делать: сохранять как в имени файла.
- [x] Проверка, что все 2906 имён парсятся регуляркой; нераспарсенные — вывести списком.
- [x] Посчитать дубликаты `group_key` (ожидается 7) и сохранить их список.

### Определение производителя (п. 4.3.2)
- [x] Начальное правило: `В` → ММК, `V`/`Z` → «Уральская Сталь» (`marking_format` = `V` или `Z`).
- [x] Визуальная проверка ~20 случайных фото на каждую группу: подпись производителя на маркировке, способ нанесения (сплошной или точечный), состав строк.
- [x] Отдельно проверить, нет ли среди фото «Северстали» (п. 4.1). Результат занести в [00-overview.md](00-overview.md), раздел «Открытые вопросы».
- [x] Зафиксировать итоговый список производителей и их доли в наборе.

## Артефакты

- Репозиторий с каркасом, `.gitignore`, `requirements.txt` (черновик).
- `scripts/audit_images.py`, `scripts/build_metadata.py`.
- `data/metadata.csv`.
- Короткая сводка по данным (в этом файле или `docs/data-audit.md`): число битых файлов, распределение по производителям, дубликаты листов, результат проверки на «Северсталь».

## Критерии готовности

- `data/metadata.csv` содержит строку для каждого из 2906 файлов, у каждой проставлены производитель и `group_key`.
- Битые файлы посчитаны и помечены.
- Соответствие префикс → производитель подтверждено визуально, расхождения зафиксированы.
- EasyOCR запускается на CPU в созданном окружении.

## Риски этапа

- Префикс не всегда однозначно определяет производителя → визуальная проверка; спорные фото помечаются вручную.
- Тяжёлые зависимости EasyOCR (torch) долго ставятся → заранее проверить время установки, это понадобится для НФТ 6 (≤ 30 мин).
