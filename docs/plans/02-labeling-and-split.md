# 02. Эталонная разметка и разбиение выборок

> **Решение 2026-11-14 (вариант B, отход от ТЗ, требует согласования с заказчиком).** Ручная разметка полного текста маркировки не делается: по пилоту надёжно прочитать точечную и размытую маркировку по кадру нельзя (путаются `0`/`8`), эталон с догадками исказил бы CER (риск 4). Вместо этого эталоном служат **плавка и номер листа из имени файла** для всех 2906 фото: `scripts/build_references.py` → `data/references.csv` (нормализация `normalize_field`: верхний регистр, только буквы и цифры). Пункты ниже со значком `[~]` заменены этим решением. Правила `docs/labeling-rules.md` относятся только к полной разметке и в варианте B не применяются. Инструмент `scripts/label_tool.py` остаётся для необязательного быстрого прохода «читаемость» (см. ниже).
>
> Открытый вопрос: критерий 11 (исключение нечитаемых только по заранее зафиксированному решению). В варианте B кадры с невидимой маркировкой остаются в тесте. Предложение: считать CER по всему тесту и, отдельно, без кадров, помеченных человеком как `unreadable` до прогона. Пометка требует только быстрого просмотра, а не набора текста.

> **Пометка читаемости (критерий 11), добавлено 2026-11-14.** `scripts/readability_tool.py` (порт 5002) показывает тестовые кадры по одному с номером плавки и листа из имени файла. Нужно за секунды решить: 1 читается (номер плавки виден целиком), 2 частично, 3 не читается (номера плавки не видно). Результат — `data/readability.csv`. OCR-ответы инструмент не показывает: решение должно быть принято до прогона на тесте. Оценка: `scripts/evaluate.py ... --exclude-unreadable` считает CER без помеченных `unreadable` и печатает, сколько исключено. В отчёте надо давать обе цифры: по всему тесту и без `unreadable`.

> **Выполнено 2026-11-15:** тест размечен по читаемости, решение и контрольная сумма — в [../readability-decision.md](../readability-decision.md). Исключается 106 из 581 кадра (18%).

## Цель

Зафиксировать правила сравнения текста, разбить данные на выборку для настройки и тестовую без утечек, создать эталонную разметку и отдельный набор повёрнутых тестовых изображений.

- п. 4.3 «Разовая подготовка», шаги 3–5: эталонная разметка, разбиение, дополнительные варианты изображений при необходимости.

## Задачи

### Правила нормализации текста (п. 4.4) — фиксируются ДО разметки
- [x] `docs/labeling-rules.md` + функция `normalize(text)` в `src/` с юнит-тестами. Одна и та же функция применяется к эталону и к выходу OCR.
- [x] Регистр: всё приводится к верхнему.
- [x] Пробелы: последовательности пробелов схлопываются в один, пробелы по краям строк удаляются.
- [x] Порядок строк: строки маркировки записываются сверху вниз в порядке чтения при правильной ориентации, разделитель — `\n`. При расчёте CER строки склеиваются через один пробел (*решение исполнителя*, чтобы порядок разбиения на строки OCR не штрафовал сильнее, чем нужно).
- [x] Алфавит: кириллица и латиница записываются так, как нанесены на листе (например, `В` в номере плавки ММК — кириллица). Похожие пары (`О`/`0`, `В`/`8`, кириллические/латинские двойники) пишутся по смыслу маркировки.
- [x] Десятичный разделитель и знак «х» в размерах (например, `12,0х3134х12040`) записываются как на маркировке; правило фиксируется в документе.
- [x] Неразборчивые символы в частично стёртой маркировке не угадываются: если символ нельзя прочитать уверенно, фото помечается и решение фиксируется (см. ниже).

### Разбиение 80/20 (п. 4.2)
- [x] `scripts/split_dataset.py`: групповое разбиение по `group_key` (все фото одного листа попадают в одну выборку), стратификация по производителю (и по `marking_format`, если групп достаточно), фиксированный seed.
- [x] Результат — `data/split.csv` (`filename`, `split` ∈ {`tune`, `test`}). Файл коммитится и больше не пересоздаётся.
- [x] Проверка: доли ≈ 80/20 в целом и в каждой группе производителя; ни один `group_key` не попал в обе выборки.
- [x] Правило процесса: скрипты подбора (этап 3) читают только `split == tune`. Тест открывается только на этапе 5.

### Инструмент разметки
- [x] Минимальный локальный инструмент (скрипт с окном OpenCV или простая локальная страница — *решение исполнителя*): показывает фото, предзаполненное текстовое поле и даёт сохранить или пометить фото.
- [x] Предзаполнение: сделано только из имени файла (номер плавки). Черновик EasyOCR в инструмент не добавлен — вернуться, если ручной ввод будет слишком долгим (решение этапа 2: сначала измерить скорость разметки).
- [x] Результат — `data/labels.csv`: `filename`, `reference_text`, `readability` ∈ {`readable`, `partial`, `unreadable`}, `comment`.

### Объём разметки (*решение исполнителя*)
- [~] Весь тест (~20%, ≈580 фото) — полная эталонная разметка.
- [~] Выборка настройки — полная разметка поднабора ~300 фото, поровну по производителям. Он нужен для подбора конвейера по полному CER.
- [~] Остальная выборка настройки — без ручной разметки. Плавку и лист из имени файла можно использовать как частичный эталон (CER по этим подстрокам) для быстрых сравнений.

### Нечитаемая маркировка (п. 4.4, критерий 11)
- [~] Фото, для которых нельзя достоверно сформировать эталон, помечаются `unreadable` при разметке — до любых прогонов модели на тесте.
- [~] Частично стёртые, но различимые (`partial`) остаются в тесте и участвуют в CER.
- [~] Количество `unreadable` по производителям фиксируется. Эта фиксация и есть «заранее зафиксированное решение» из критерия 11.

### Проверка качества разметки (риск 4)
- [~] Повторная выборочная проверка ~10% разметки теста (желательно другим человеком или через день). Исправленные ошибки записываются.
- [~] Автопроверка: номер плавки и лист в `reference_text` совпадают с именем файла (там, где они видны на маркировке).

### Повёрнутый тестовый набор (ФТ 3, критерий 5)
- [x] `scripts/make_rotated_set.py`: для тестовых фото (или их стратифицированного поднабора) создаются копии, повёрнутые на 90°, 180° и 270°, в `data/rotated/` (не коммитится, генерируется скриптом).
- [x] Эталон повёрнутой копии совпадает с эталоном исходного фото.
- [x] Аналогично генерируются повёрнутые копии из выборки настройки — для подбора логики ориентации на этапе 3.

### Аугментации (п. 4.3.5)
- [x] По умолчанию не делаются: модель не обучается (п. 8). Возвращаемся к ним, только если на этапе 3 понадобится подбирать препроцессинг на искусственно ухудшенных изображениях.

- Правила нормализации зафиксированы до начала разметки.
- `data/split.csv` создан, проверки на утечки и стратификацию пройдены.
- Весь тест размечен, `unreadable` отмечены и посчитаны, выборочная перепроверка проведена.
- Поднабор выборки настройки (~300) размечен.
- Скрипт повёрнутого набора работает.

## Риски этапа

- Разметка занимает больше времени, чем ожидается → предзаполнение из имени файла и OCR; при нехватке времени сначала размечается тест, потом поднабор настройки.
- Неоднозначные символы (`О`/`0`, `В`/`8`) размечаются непоследовательно → правила в `docs/labeling-rules.md` + перепроверка.
- Мало групп в одном из производителей для стратификации по `marking_format` → стратифицируем только по производителю.
