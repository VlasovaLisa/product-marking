# 00. Обзор плана реализации

**Источник истины:** [`docs/tech-task.pdf`](../tech-task.pdf) — ТЗ «Создание системы автоматического считывания маркировки продукции». Если план расходится с ТЗ, прав ТЗ. Всё, чего в ТЗ нет, помечено в планах как *решение исполнителя*.

## Цель

MVP-веб-приложение, которое распознаёт буквенно-цифровую маркировку на фото металлических прокатных листов готовой предобученной OCR-моделью и даёт пользователю вручную исправить результат (ТЗ п. 1, 2.2).

- Основная метрика: **CER ≤ 30%** на тестовой выборке (п. 3.2).
- Дополнительная метрика: **≤ 60 с** на изображение на рекомендованном оборудовании, без обязательного GPU (п. 3.2, НФТ 2, 4).

## Стек (НФТ 3)

Python 3.10+, EasyOCR, OpenCV, Flask. PaddleOCR допускается при недостаточном качестве EasyOCR (п. 5).

## Исходные данные: что есть фактически

- `images/`: 2906 JPG, 1280×720, ~655 МБ (совпадает с п. 4.1: «2906 изображений»).
- Формат имени файла: `Труба №<id> Плавка №<год>-<префикс><номер> Лист №<номер>.jpg`. В имени уже есть номер плавки и номер листа — это частичная разметка.
- Группы по префиксу плавки:

| Префикс | Кол-во | Номер листа | Предположительный производитель |
|---|---|---|---|
| `В` (кириллица) | 1611 | 9 цифр | ПАО «ММК» (на фото видно «ММК») |
| `Z` | 842 | 1–2 цифры | АО «Уральская Сталь» (точечная маркировка) |
| `V` | 453 | 1–2 цифры | АО «Уральская Сталь» (точечная маркировка) |

- 7 пар «плавка + лист» встречаются дважды: один и тот же лист снят несколько раз (учитывается в п. 4.2).
- В левом верхнем углу каждого кадра есть оверлей камеры (например, «ГД42 22:35:01»). Его нужно исключать из распознавания.

## Что НЕ делаем (п. 8 ТЗ, «В MVP не входят»)

1. Интеграцию с учётными системами предприятия.
2. Подключение видеокамер и обработку видеопотока.
3. Обучение нейросети с нуля и автоматическое дообучение.
4. Автоопределение маршрута листа.
5. Регистрацию пользователей и права доступа.
6. Хранение истории распознаваний в БД.
7. Гарантированное извлечение параметров в структурированные поля.
8. Восстановление полностью стёртых символов.
9. Гарантированное распознавание любого изображения.
10. Отдельную модель под каждого производителя.

## Решения исполнителя (сверх ТЗ)

- **Объём разметки.** Полностью размечаются весь тест (~20%, ≈580 фото) и поднабор выборки настройки (~300 фото). Для остальной выборки настройки частичным эталоном служат плавка и лист из имени файла. ТЗ требует CER именно на тестовой выборке, поэтому полная разметка всех 2906 фото не нужна.
- **Производители.** Стратификация и метрики считаются по фактически присутствующим группам, а не по трём из ТЗ (см. ниже).
- **Маскирование оверлея камеры** — часть предобработки.
